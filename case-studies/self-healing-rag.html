Self-healing RAG and answer validation pipeline

A retrieval-augmented generation pipeline that checks its own answers, retries with a better query when they are unsupported, and refuses safely rather than guessing.

The problem

A basic RAG system retrieves passages and generates an answer, and has no way to notice when the answer is not supported by what it retrieved. In production that shows up as confident, ungrounded text.

What I built

A LangGraph workflow with explicit stages for retrieval, generation, hallucination detection, query reformulation and fallback handling. A critic agent compares each answer with the retrieved passages. If the answer is unsupported, the graph reformulates the query and retrieves again. If it still cannot be supported, the system returns a safe insufficient-information response.

The corpus was 5,000 documents split into 12,000 vector chunks.

Why it is built this way

Putting the check inside the graph, rather than after it, makes every decision visible: which passages were used, why an answer was rejected, and what the retry changed. That is what you need to debug and to evaluate the system.

Try the idea

The box at the top of the home page is a tiny version of the same pattern: it retrieves from this site, checks that the question is supported, and says so when it is not.
