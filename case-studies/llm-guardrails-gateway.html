The problem

Prompt injection, jailbreaks, personal data in prompts, toxic output and malformed structured output are separate failures, and application teams rarely want to rebuild checks for each one.

What I built

A gateway with a YAML policy engine. Policies are configuration, not code, so they can be reviewed, versioned and changed without redeploying. It validates input and output, enforces JSON schemas and topic relevance, and triggers automatic retries or safe fallbacks when validation fails.

It was validated on 2,000 adversarial prompts covering prompt injection, jailbreaks, PII leakage, toxicity, off-topic responses and schema violations.

Why policies as configuration

The people who decide what is acceptable are often not the people who write the application. Keeping policies in a readable file lets them be reviewed and audited on their own.
